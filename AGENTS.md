# netCatalog

CLI для получения доменов, IP-адресов и CIDR-подсетей сервисов.
Команда `update` скачивает каталоги; поиск и получение данных работают по локальным
снимкам без HTTP, DNS и WHOIS. Программа не меняет настройки сети или маршруты роутера.
Подробная справка находится в [README.md](README.md).

## Источники

| Источник | Репозиторий | Какие данные использует программа |
| --- | --- | --- |
| iplist | [rekryt/iplist](https://github.com/rekryt/iplist) | Порталы с доменными идентификаторами; полная JSON-выгрузка с полями `domains`, `ip4`, `ip6`, `cidr4`, `cidr6`: домены, отдельные IPv4/IPv6 и подсети обоих семейств. |
| v2fly | [v2fly/domain-list-community](https://github.com/v2fly/domain-list-community) | Именованные списки из готовой YAML-выгрузки релиза `dlc.dat_plain.yml`; только домены из `domain`-правил. IP-адреса и CIDR этот адаптер не возвращает. |

- iplist скачивается целиком одним запросом при `update`, без выбора портала или группы.
  Группы источника не участвуют в поиске сервисов.
- Для v2fly используется [выгрузка последнего релиза](https://github.com/v2fly/domain-list-community/releases/latest/download/dlc.dat_plain.yml).
  Правила `full`, `keyword`, `regexp` игнорируются; имена с префиксом `category`
  и имена с дефисом исключены из каталога.
- Источники сохраняются независимо. Неудачное обновление оставляет предыдущий снимок.
- CIDR iplist — исходные подсети без upstream `replace`-замен. Они могут включать
  другие сервисы.

## Стек и устройство

- **Go 1.22+**, версии зависимостей закреплены в `go.mod` и `go.sum`.
- **Cobra** — команды, флаги, проверка аргументов и справка CLI.
- **`golang.org/x/term`** — определение терминала для цветных предупреждений.
- **`gopkg.in/yaml.v3`** — разбор YAML-выгрузки v2fly.
- Стандартная библиотека: `net/http` для загрузки, `encoding/json` для JSON,
  `net/netip` для IP/CIDR, `context.Context` для отмены выполнения.
- **`testing`**, **Testify** (`assert`/`require`) и **`net/http/httptest`** — тесты.
- **gofmt** — форматирование; **golangci-lint v2** — линтинг.

- `main.go` — точка входа; 
- `app/` — команды и вывод; 
- `internal/resolver/` — поиск и объединение результатов; 
- `internal/providers/` — адаптеры источников;
- `internal/catalogstore/` — локальные снимки; 
- `test/` — все тесты.

Каждый вызов `app.Run` создаёт независимое дерево команд без общего состояния флагов.

## Команды разработки

| Команда | Назначение |
| --- | --- |
| `go build -o bin/netCatalog .` | Собрать исполняемый файл в `bin/netCatalog`. |
| `go run . --help` | Запустить приложение из исходников и показать справку. |
| `go test ./...` | Запустить все тесты проекта. |
| `go test -race ./...` | Запустить все тесты с проверкой гонок данных. |
| `go test ./test/app -run TestRunGetDomains -count=1` | Запустить конкретный тест без использования кэшированного результата. |
| `go vet ./...` | Выполнить статические проверки Go. |
| `make fmt` | Применить gofmt к `main.go`, `app/`, `internal/`, `test/`; изменяет файлы. |
| `make fmt-check` | Проверить форматирование без изменения файлов. |
| `make lint` | Запустить установленный golangci-lint для реализации и тестов. |
| `make check` | Выполнить `fmt-check`, затем `lint`; не изменяет исходники и не запускает тесты. |
| `go doc ./internal/resolver` | Прочитать GoDoc пакета resolver. |

Пути к инструментам можно задать явно:

```sh
# Проверить форматирование и линт указанными инструментами
make check GOFMT=/path/to/gofmt GOLANGCI_LINT=/path/to/golangci-lint
```

Перед завершением изменений запускать `make check` и `go test -race ./...`.

## Команды CLI и примеры

После сборки используйте `bin/netCatalog`; вместо него можно писать `go run .`.

```sh
# Скачать и сохранить каталоги обоих источников перед первым чтением
bin/netCatalog update

# Обновить только iplist
bin/netCatalog update --source iplist

# Показать все поддерживаемые источники и типы данных
bin/netCatalog sources

# Показать сервисы из локальных каталогов
bin/netCatalog services list

# Найти сервисы по подстроке в домене или имени списка
bin/netCatalog services search telegram

# Получить домены; короткое имя объединяет discord.* и список discord из v2fly
bin/netCatalog get discord --type domains

# Получить домены только из v2fly
bin/netCatalog get discord --type domains --source v2fly

# Получить отдельные IP обоих семейств из iplist
bin/netCatalog get youtube --type ips --family all

# Получить IPv6-подсети из iplist
bin/netCatalog get youtube --type cidrs --family ipv6

# Выбрать точный портал iplist из локального снимка
bin/netCatalog get youtube.com --type domains --source iplist

# Включить предупреждения в stderr
bin/netCatalog get telegram --type domains --info

# Обновить и читать отдельный набор каталогов по одному и тому же пути
bin/netCatalog update --data-dir ./catalogs
bin/netCatalog services search telegram --data-dir ./catalogs

# Показать общую справку и справку конкретной команды
bin/netCatalog --help
bin/netCatalog get --help
```

- `--type domains|ips|cidrs` обязателен для `get`.
- `--family ipv4|ipv6|all` применяется к IP/CIDR, по умолчанию `ipv4`; для доменов запрещён.
- `--source iplist|v2fly` ограничивает источник для обновления и чтения. v2fly поддерживает только домены.
- `--iplist-url`, `--v2fly-url`, `--timeout` действуют только для `update`.
- Вывод — текст, одна запись на строку, с сортировкой и удалением дубликатов;
  данные идут в `stdout`, ошибки и включённые предупреждения — в `stderr`.
  Флага `--format` нет.
- Коды завершения: `0` — успех (для чтения также пустой/частичный результат),
  `1` — ошибка выполнения или записи, `2` — неверные аргументы либо неизвестный/
  неоднозначный сервис. Для `update` сбой любого выбранного источника даёт `1`.

## Правила написания тестов

- Все тесты держать в корневой `test/`, по группам: `app/`, `catalogstore/`,
  `resolver/`, `providers/iplist/`, `providers/v2fly/`.
- Одна функция `Test<Method><Scenario>` проверяет один метод и один сценарий.
  Для разных условий писать отдельные функции: без таблиц сценариев и вложенных `t.Run`.
- Несколько проверок допустимы в одном сценарии. Использовать `require` для условий,
  без которых нельзя продолжать тест, и `assert` для независимых ожиданий.
- Общую подготовку выносить в тестовые helpers с `t.Helper()`;
  освобождение ресурсов и восстановление состояния оформлять через `t.Cleanup()`.
- HTTP проверять локальными серверами `httptest`, без обращений к публичным источникам.
- Тесты команд запускать через `app.Run`. Помощник `runForTest` задаёт временную
  папку каталогов и отключает публичную загрузку v2fly по умолчанию.
- Тесты, меняющие окружение, потоки процесса или общий HTTP-транспорт,
  не запускать параллельно.
- Тестовые файлы не исключать из линтинга; проверять весь проект с `-race`.
- Экспортируемые символы и пакеты документировать в GoDoc: комментарий перед
  объявлением начинается с имени символа или `Package <name>` и описывает контракт,
  ошибки, ограничения и частичные результаты.
