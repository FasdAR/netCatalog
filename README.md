# netCatalog

CLI на Go для получения доменов, IP-адресов и CIDR-подсетей сервисов.
Подключены публичный [iplist](https://github.com/rekryt/iplist) и готовая YAML-выгрузка
[v2fly/domain-list-community](https://github.com/v2fly/domain-list-community).
`netCatalog update` скачивает источники и сохраняет локальные снимки. Поиск и получение
данных работают **без HTTP**, только по этим снимкам.

## Сборка

Нужен Go 1.22 или новее.

```sh
go build -o bin/netCatalog .
go test -race ./...
go vet ./...
```

Вместо сборки можно запускать `go run . ...`.
Для команд и help используется Cobra, для определения терминала —
`golang.org/x/term`, для разбора YAML — `gopkg.in/yaml.v3`.
Тесты используют стандартный `testing` и Testify (`assert`/`require`).
Все тесты находятся отдельно от реализации в корневой папке `test/`.
Версии зависимостей совместимы с Go 1.22 и зафиксированы в `go.mod` и `go.sum`.

## Форматирование и линтер

Нужны `make`, `gofmt` и **golangci-lint v2**, совместимый с `.golangci.yml`. 
Makefile запускает установленный линтер.

```sh
make fmt        # применить gofmt к main.go, app/, internal/ и test/
make fmt-check  # проверить форматирование без изменения файлов
make lint       # запустить golangci-lint для кода и тестов
make check      # fmt-check, затем lint; не изменяет исходники
go test -race ./...
```

В `.golangci.yml` включены `govet`, `staticcheck`, `errcheck`, `revive` и
`testifylint`: ошибки кода, непроверенные ошибки, стиль/GoDoc и использование
Testify. Тестовые файлы не исключаются. `make check` не запускает тесты:
их проверяем отдельной командой выше. Папка `docs/` остаётся историей;
форматирование её не затрагивает.

## Использование

```sh
# Сначала скачать актуальные каталоги обоих источников
bin/netCatalog update

# Обновить только выбранный источник
bin/netCatalog update --source iplist
bin/netCatalog update --source v2fly

# Локальный каталог порталов iplist и имён списков v2fly
bin/netCatalog services list
bin/netCatalog services search telegram
# telegram и telegram.org (если они присутствуют в выбранных источниках)

# Домены: по одному на строку, без префиксов
bin/netCatalog get youtube --type domain

# Показать предупреждения (оранжевые в терминале, в stderr)
bin/netCatalog get telegram --type domain --info

# Использовать только выбранный источник
bin/netCatalog get discord --type domain --source v2fly
bin/netCatalog services list --source iplist
bin/netCatalog services search telegram --source v2fly

# Отдельные IP / подсети; IPv4 по умолчанию
bin/netCatalog get youtube --type ip
bin/netCatalog get youtube --type cidr --family ipv4
bin/netCatalog get youtube --type cidr --family ipv6
bin/netCatalog get youtube --type ip --family all

# Точный домен выбирает только этот портал
bin/netCatalog get youtube.com --type domain

# Точный портал только из iplist
bin/netCatalog get youtube.com --type domain --source iplist

# Собственный экземпляр iplist или другой публичный портал
bin/netCatalog update --source iplist --iplist-url https://iplist.opencck.org/ --timeout 15s
bin/netCatalog get youtube --type ip

# Изолированный набор снимков: одинаковый --data-dir для записи и чтения
bin/netCatalog update --data-dir ./catalogs
bin/netCatalog services search telegram --data-dir ./catalogs

bin/netCatalog sources
bin/netCatalog --help
```

Каталог строится из локальных снимков при каждом вызове, без заданных вручную соответствий.
Запись — портал с доменом (`telegram.org`) либо именованный список (`telegram`).
Домен для имени списка не угадывается и не задаётся вручную.

Группы iplist (`messengers`, `youtube` и т. п.) не участвуют в поиске и выборе сервиса.
`services search telegram` ищет подстроку в доменах и именах списков и выводит
имена по одному на строку; соседние порталы группы iplist не добавляются.
`services list` и `services search` выводят короткие имена без доменной зоны
(`telegram.org` → `telegram`), отсортированные и без дубликатов: портал iplist и
список v2fly с одним именем показываются один раз.

`get` сначала ищет точное совпадение домена. Короткое имя без точек (`discord`)
выбирает **все** порталы, чья первая часть имени целиком совпадает: `discord.com`,
`discord.gg`, `discord.media`. `discord-tools.com`, `notdiscord.com` и
`cdn.discord.com` не подходят. Для каждого портала читаются локальные данные, затем
списки объединяются с удалением дубликатов. При запросе доменов добавляется также
именованный список `discord` из v2fly. Для `ip` и `cidr` используется только iplist;
снимок v2fly при таких командах не читается. Сбой одного источника не мешает
вернуть данные остальных. Сервис, который есть только в v2fly, также доступен по имени.

`get --output-dir DIR` вместо вывода в терминал записывает записи в `DIR/СЕРВИС/ТИП.md`
(`domain.md`, `ip.md`, `cidr.md`), по одной на строку; каталоги создаются, файл
перезаписывается, файлы других типов не затрагиваются. При ошибке ничего не создаётся.
Имя каталога — имя выбранного сервиса (`discord`, либо точный домен `discord.com`).

`--source iplist|v2fly` ограничивает источник для `update`, `get` и `services list/search`:
обновляется или читается только выбранный источник. Остальные источники не запрашиваются,
их URL не проверяются. Без флага используются все подходящие источники.
Можно выбрать только один источник. Неизвестное значение даёт код `2`.
`--source v2fly` поддерживает только `--type domain` для `get`;
нарушения дают код `2` до чтения снимков.
`sources` всегда показывает все поддерживаемые источники, независимо от `--source`.

`get` не ищет по подстроке: если нет ни точного домена, ни совпадения по первой части,
команда завершается с кодом `2`. Подстроки ищет `services search`. `get discord.com` получает данные только
этого портала iplist, без подключения всего списка `discord` из v2fly.
`services search` выводит найденные короткие имена без дубликатов.

Совпадение первой части — **эвристика**, а не подтверждение общего владельца доменов.
Соответствия не задаются вручную; разные имена одной компании автоматически не объединяем.

Каталог iplist ограничен HTTP-порталом, выбранным при `update`; другие порталы могут
содержать другие идентификаторы и автоматически не подключаются. Полная выгрузка
`?format=json` содержит все порталы сервера и их `domains`, `ip4`, `ip6`, `cidr4`, `cidr6`.
`update` получает её одним запросом, без `site`, `group`, `data` и исключающих фильтров.
Отдельно обходить каждый портал не нужно. Точный домен в `get` выбирает портал из
локального снимка, без обращения к сети; неизвестное имя даёт код `2`.

### Обновление и локальное хранение

Снимки источников независимы: `iplist.snapshot` и `v2fly.snapshot`. Каждый содержит
JSON-строку метаданных (версия формата, источник, URL и время обновления UTC),
а затем исходный JSON или YAML. Это внутренний контейнер, не отдельный чистый JSON/YAML-файл.

Каталог по умолчанию — папка `source` рядом с исполняемым файлом
(например, `bin/source` для `bin/netCatalog`; символические ссылки разворачиваются).
При запуске через `go run .` бинарник находится во временной папке, поэтому
используйте `--data-dir` или собранный `bin/netCatalog`.

Обновление поддерживается на Unix-платформах (включая macOS и Linux). На Windows
публикация снимка пока отклоняется с кодом `1`: стандартный `os.Rename` не гарантирует
атомарность. Предыдущие данные остаются нетронутыми; чтение готовых снимков доступно.

`--data-dir PATH` переопределяет путь для записи и чтения. В одном каталоге хранится
один снимок каждого источника. Обновление с другим URL заменяет только выбранный
снимок; для нескольких наборов используйте разные `--data-dir`.

`--iplist-url`, `--v2fly-url` и `--timeout` действуют **только для `update`**.
Команды чтения игнорируют их и не выполняют HTTP, DNS или WHOIS. Автоматического
обновления, TTL и сетевого fallback нет. До первого использования выполните `update`.

Новые данные проверяются и записываются во временный файл в том же каталоге,
затем атомарно заменяют старый снимок вместе с метаданными. Сбой HTTP, формата,
лимита, отмена или ошибка записи сохраняют предыдущую исправную копию.
Если один источник обновился, а другой нет, успешная копия остаётся, но `update`
возвращает код `1` и всегда сообщает ошибку в stderr. Код `0` означает успех всех
выбранных источников; неверные аргументы — код `2`.

`update --v2fly-url ''` обновляет только iplist. Явный
`update --source v2fly --v2fly-url ''` запрещён. При чтении пустой `--v2fly-url`
не отключает сохранённый v2fly: используйте `--source iplist`.

Отсутствующий или повреждённый снимок не скачивается автоматически. Явный выбор
такого источника даёт код `1` с рекомендацией `netCatalog update --source SOURCE`.
Без `--source` доступные снимки могут дать частичный результат; причины пропуска
показываются с `--info`. Если недоступны все применимые источники — код `1`.
Пустые корректные массивы данных считаются успешным чтением.

Внутренний каталог хранит имена, необязательные домены и привязки к источникам. Привязки содержат
идентификатор источника и его непрозрачный
ключ: для iplist это портал, для v2fly — имя списка, для будущего источника это может быть файл или ID.
Одинаковые домены разных источников объединяются с сохранением всех привязок;
их внутренние ключи не участвуют в пользовательском поиске.

В примерах флаги указываются после команды и позиционного аргумента.
Cobra формирует help для каждой команды: `netCatalog get --help`,
`netCatalog services search --help`. Help не обращается к HTTP-источникам.
`--type` обязателен. `--family` имеет значения `ipv4`, `ipv6`, `all` и запрещён для доменов.
Флага `--format` нет: вывод всегда текстовый, одна запись на строку.

### Вывод и ошибки

- Данные — в `stdout`, предупреждения — в `stderr`.
- По умолчанию предупреждения скрыты: `get` выводит только домены, IP или CIDR.
  Флаг `--info` включает предупреждения для `get` и `services list/search`.
  В терминале они оранжевые (ANSI 256-color, цвет 208); при перенаправлении `stderr`
  в файл/pipe, наличии переменной `NO_COLOR` (в том числе пустой) или `TERM=dumb`
  используются обычные строки без ANSI-кодов. Для определения терминала используется
  `golang.org/x/term`, без собственных платформенных системных вызовов.
- Недоступные снимки и некорректные записи пропускаются при частичной выдаче.
- Код завершения `0` для чтения: хотя бы одно успешное логическое чтение, в том числе пустой или частичный результат.
- Код `1`: недоступен весь каталог/все чтения неудачны либо невозможно записать результат;
  для `update` — сбой хотя бы одного выбранного источника.
- Код `2`: неверные аргументы, неизвестный сервис.
- Ошибки аргументов и полный сбой получения каталога/данных всегда видны в `stderr`,
  даже без `--info`. При частичном результате код остаётся `0`, а подробности
  пропущенных источников видны только с `--info`. Ошибки `update` видны всегда.
- Таймаут `update` по умолчанию — 30 секунд **на запрос**. Ctrl+C отменяет обновление.
- Ответ iplist ограничен 64 MiB, YAML-релиз v2fly — 32 MiB.
  Превышение лимита или повреждённая схема не заменяют старый снимок.
- Результат сортируется, точные дубликаты удаляются.

Домены, IP и CIDR выводятся по одному на строку без префиксов и метаданных.
Например, список доменов:

```text
discord.com
discord.gg
```

Это список значений. Тип доменного правила
сохраняется во внутренней модели, но не выводится в CLI. Адаптер по-прежнему
использует JSON для обмена с iplist; пользовательский JSON-вывод удалён.

## Источник v2fly

По умолчанию используется готовая выгрузка последнего релиза:

```text
https://github.com/v2fly/domain-list-community/releases/latest/download/dlc.dat_plain.yml
```

- Исходники `data/` не читаются: включения и affiliations уже обработаны upstream.
- Имена, начинающиеся с `category`, и любые имена с дефисом исключены из каталога.
  Это временный фильтр: дефис не обязательно означает сборку нескольких сервисов.
- Возвращаются **только `domain`-правила**. `full`, `keyword`, `regexp` игнорируются;
  сведения о пропусках видны с `--info`.
- Атрибуты в строках вида `domain:example.com:@ads` не попадают в доменное имя.
- Имена списков используются как имена сервисов; соответствий `discord → discord.com`
  в коде нет. Списки, доступные только в v2fly, не зависят от каталога iplist.
- Вся выгрузка скачивается при `update` и сохраняется между вызовами.
  При поиске локальный снимок разбирается один раз на команду.
- Другую выгрузку можно указать при `update --v2fly-url URL`, например закреплённый релиз.

```sh
bin/netCatalog get discord --type domain
bin/netCatalog get discord --type domain --info
bin/netCatalog get discord --type domain --source iplist
```

### Добавление источника

1. Создать пакет `internal/providers/<source>` с реализацией `resolver.Provider`.
2. Реализовать `ListServices`: обнаруживать доменные идентификаторы или именованные
   списки (`Service.Name`, если домена нет) и их привязки `Binding{Source, Key}`.
   Если источник не сообщает домен, не угадывать его по имени.
3. Реализовать `Fetch(ctx, key, query)`: интерпретировать свой ключ и переводить данные
   в `Entry`, сохраняя тип доменного правила. Зарегистрировать адаптер в
   `Resolver.Providers` в CLI; при необходимости добавить параметры его подключения.
4. Добавить тесты в `test/providers/<source>/`. Resolver уже объединяет результаты нескольких адаптеров,
   сохраняет источники и не смешивает `full` и `suffix` для одного домена.

Новый URL существующего iplist-формата задаётся через `--iplist-url`; новый формат требует
нового адаптера и загрузчика для `update`. Динамических плагинов нет;
источники хранятся отдельными локальными снимками.

### Добавление команды

Команды находятся в `app/`. Каждая создаётся отдельной функцией-конструктором,
которая задаёт описания, `Args`, обработчик `RunE` и флаги.
Новую команду подключайте через `AddCommand` в конструкторе родительской команды.
Имена вложенных файлов приводим к виду `example_list.go`.
Тесты команд добавляйте в `test/app/` и запускайте через `app.Run`.

Используйте `cmd.Context()`, `cmd.OutOrStdout()` и `cmd.ErrOrStderr()`;
обработчики возвращают ошибки, а не вызывают `os.Exit`. Коды завершения
и ошибки записи обрабатываются централизованно в `app/execute.go`.
Конфигурационные файлы и Viper не используются.

Каждый вызов `app.Run` создаёт независимое дерево команд: флаги, аргументы,
контекст и потоки не сохраняются между вызовами. Помощник `runForTest` задаёт
временную папку каталогов и отключает публичную загрузку v2fly по умолчанию.
Тесты, меняющие окружение или общий HTTP-транспорт, не запускаются параллельно.

## Тесты и документация кода

- Одна функция `Test<Method><Scenario>` проверяет один метод и один сценарий.
  Для разных условий создаются отдельные функции, без таблиц сценариев и вложенных `t.Run`.
- Несколько assertions допустимы для одного сценария. `require` проверяет условия,
  без которых тест не может продолжаться; `assert` — независимые ожидания.
- Общая подготовка находится в тестовых helpers с `t.Helper()` и `t.Cleanup()`.
  HTTP проверяется локальными серверами `httptest`, без публичных источников.
- Экспортируемые символы и пакеты документируются в формате GoDoc:
  комментарий перед объявлением, начиная с имени символа или `Package <name>`.
  Комментарии описывают контракт, ошибки, ограничения и частичные результаты.
  Документацию можно читать через `go doc ./internal/resolver` и подсказки IDE.
