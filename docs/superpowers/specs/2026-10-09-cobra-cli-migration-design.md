# Переход на шаблоны cobra-cli

## Цель

Полностью убрать `internal/cli/`, объединить существующий CLI и результат
`cobra-cli init` в стандартной структуре генератора. Пользователь выбрал
глобальные команды и регистрацию через `init()`, а не конструкторы дерева.

## Структура

- `main.go`: единственная точка входа; создание контекста отмены по Ctrl+C,
  вызов `cmd.Execute`, освобождение signal context и завершение с нужным кодом.
- `cmd/root.go`: глобальный `rootCmd`, общие параметры и persistent-флаги.
- `cmd/get.go`: глобальный `getCmd`, локальные флаги, валидация и выполнение.
- `cmd/services.go`, `cmd/services_list.go`, `cmd/services_search.go`:
  родительская команда и две дочерние команды с регистрацией через `init()`.
- `cmd/sources.go`, `cmd/sources_list.go`: родительская команда и список источников.
- `cmd/execute.go`: выполнение дерева, обработка ошибок и кодов завершения,
  контроль ошибок записи, включая help. Не вызывает `os.Exit`.
- `cmd/warnings.go`: существующий вывод предупреждений и определение цвета.
- `cmd/catalogue.go`: создание провайдеров и загрузка каталога для команд.
- Тесты из `internal/cli/` переносятся в пакет `cmd`.

Старые `internal/cli/` и `cmd/netCatalog/main.go` удаляются после переноса.
`internal/resolver/` и `internal/providers/` не изменяются.

## Использование генератора

Повторный `cobra-cli init` не нужен. Для отсутствующих файлов используются
`cobra-cli add get`, `cobra-cli add services`, `cobra-cli add sources`.
Вложенные команды создаются с уникальными Go-именами:
`cobra-cli add servicesList -p servicesCmd`,
`cobra-cli add servicesSearch -p servicesCmd`,
`cobra-cli add sourcesList -p sourcesCmd`.
После генерации имена файлов приводятся к указанной структуре, а `Use`
дочерних команд задаётся как `list`, `search TERM`, `list` соответственно.
Заготовки адаптируются к существующему поведению без возврата к конструкторам.
Если генератора нет в PATH, сначала проверяется Go bin directory; установка
инструмента не добавляет cobra-cli в зависимости приложения.

## Контракт выполнения

`cmd.Execute(ctx context.Context) int` выполняет глобальный rootCmd с аргументами
процесса и стандартными потоками. Внутренний помощник выполнения принимает
аргументы и потоки для тестов. Настройка выполняется до ExecuteContext.
В обычном процессе дерево выполняется один раз.

Сохраняются все существующие команды, значения флагов по умолчанию и ограничения.
Данные выводятся в stdout, диагностика в stderr. Предупреждения включаются
только с `--info`; сохраняются NO_COLOR, TERM=dumb и определение терминала.
Коды: 0 — успешный, частичный или пустой результат; 1 — ошибка выполнения
или записи; 2 — неверный ввод, неизвестный или неоднозначный сервис.
Help и неверные аргументы не должны инициировать HTTP-запросы.
Отключённые источники и ненужный для IP/CIDR источник v2fly не запрашиваются.
Completion остаётся отключённым. Шаблонный флаг toggle удаляется.
Viper, новые команды и изменения правил поиска не добавляются.

## Тесты

Существующие тесты сохраняются. Перед каждым тестовым выполнением помощник
сбрасывает значения флагов, включая привязанные переменные, и Changed на всём
дереве; также очищает состояние потоков, контекста и аргументов выполнения.
Тесты глобального дерева не запускаются параллельно. Повторный вызов с --info
и затем без него проверяет корректность тестовой изоляции, а не новую гарантию
публичного API. Дополнительно проверяется отсутствие переноса локальных флагов,
включая Changed для --family. HTTP-тесты используют только httptest.

## Сборка и документация

README переводится на `go run .` и `go build -o bin/netCatalog .`, описывает
структуру и добавление команд через cobra-cli. Makefile включает корневой
main.go в fmt и fmt-check. Go 1.22 и зависимости приложения сохраняются.
Пользовательские изменения .gitignore, go.mod, go.sum и LICENSE не откатываются;
лицензия не выбирается и не заменяется в рамках этой миграции.

## Проверка результата

Запускаются `go test -race ./...`, `go vet ./...`, сборка корневого пакета,
fmt-check и golangci-lint закреплённой версии при доступности инструмента.
Проверяются help корневой и вложенных команд и sources list без сети.
Изменения не коммитятся автоматически без отдельного запроса пользователя.
