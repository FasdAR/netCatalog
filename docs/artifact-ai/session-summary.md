# Итоги AI-сессии: netcraze

## Цель

Создать CLI на Go, который по имени сервиса получает домены, IP или CIDR из
расширяемого набора источников. Основной сценарий использования — подготовка
списков для маршрутизации на Keenetic. Пользователь — Kotlin-разработчик;
пояснения Go с аналогиями Kotlin включены в README.

## Реализовано

- CLI `bin/netcraze` с командами `get`, `services list/search`, `sources list`.
- Источники: публичный iplist и YAML-релиз v2fly/domain-list-community.
- Типы данных: `domains`, `ips`, `cidrs`; семейства IP: `ipv4`, `ipv6`, `all`.
- Вывод: одна запись на строку, без префикса `domain:` и без JSON.
- Флаг `--format` удалён.
- Кеша между командами и локального хранения полученных списков нет.
- Ошибочные запросы и некорректные записи пропускаются, полученные данные возвращаются.
- Результат сортируется; точные дубликаты удаляются.
- Предупреждения по умолчанию скрыты. `--info` включает их в `stderr`.
- Предупреждения оранжевые в терминале macOS/Linux. При перенаправлении `stderr`,
  наличии `NO_COLOR` или `TERM=dumb` цвет отключается.
- Ошибки аргументов и полный сбой получения данных остаются видимыми без `--info`.
- Ctrl+C отменяет HTTP-запрос через `context.Context`.
- Программа не изменяет маршруты роутера и не генерирует файл импорта Keenetic.

## Контракт и выбор сервисов

Основные контракты находятся в `internal/resolver/resolver.go`:

- `Provider` — интерфейс источника: возможности, обнаружение сервисов, получение данных.
- `Service` — имя, необязательный домен, привязки к источникам.
- `Binding` — идентификатор источника и непрозрачный ключ, понятный только адаптеру.
- `Selection` — пользовательское имя и выбранные записи каталога.
- `Resolver` — построение каталога, получение и объединение результатов.

Соответствия сервисов не прописываются вручную. Каталог строится при выполнении команды.
Группы iplist, например `messengers`, не определяют сервис и не участвуют в поиске.

Правила выбора:

1. Точный домен выбирает соответствующий портал: `get discord.com` не подключает
   весь список `discord` из v2fly.
2. Короткое имя `discord` выбирает порталы `discord.*` с полным совпадением первой
   части имени и именованный список `discord` из v2fly при запросе доменов.
3. `discord-tools.com`, `notdiscord.com`, `cdn.discord.com` не подходят под правило
   выбора порталов `discord.*`.
4. Если совпадений по имени/первой части нет, используется поиск по подстроке:
   единственный результат выбирается, несколько требуют уточнения.
5. `services search` выводит отдельные идентификаторы: например, `telegram` и
   `telegram.org`, если они доступны в источниках.

Совпадение первой части домена — эвристика, а не доказательство общего владельца.
Все связанные домены компании автоматически не определяются.

## Источник iplist

Репозиторий: https://github.com/rekryt/iplist

Публичный API: https://iplist.opencck.org/

Адаптер: `internal/iplist/provider.go`.

- Каталог получается из полной JSON-выгрузки `?format=json`.
- Каждый портал становится записью с доменным идентификатором.
- Данные выбранного портала запрашиваются через `site=`, а не `group=`.
- Внутренний HTTP-формат остаётся JSON; удалён только пользовательский JSON-вывод.
- `--url` заменяет адрес iplist. `--site` обходит обнаружение и запрашивает точный портал.
- IPv4/IPv6 запрашиваются независимо. Ответ ограничен 64 MiB.
- IP/CIDR проверяются через `net/netip`; подсети не расширяются и не агрегируются.

Пример запроса:

```text
https://iplist.opencck.org/?format=json&site=discord.com&data=domains
```

### Результаты исследования upstream

В проверенной во время сессии конфигурации репозитория обнаружены 234 конфигурации
и четыре внешних URL. В публичном API было 229 порталов и те же внешние ссылки.
Это наблюдение на момент проверки, а не постоянное свойство источника.

Внешние источники:

- YouTube: `nickspaargaren/no-google`, файл `categories/youtubeparsed` — домены.
- Autodesk: `worker.iplist.opencck.org` — домены, CIDRv4, CIDRv6.

Для Telegram и Discord списки `external` были пустыми. Данные берутся из конфигов
и дополняются через DNS. Среди настроенных DNS: локальный Docker DNS, Яндекс,
Google, Cloudflare. Далее системный `whois` и обработка диапазонов используются
для получения CIDR. Результаты обновлений сохраняются upstream в конфиги и
добавляются к прежним адресам: это накопительный агрегатор, не только текущий DNS-снимок.

В каталоге встречались недоменные ключи `jetbrains@cdn`, `jetbrains@grazie.ai`.
Наш адаптер пропускает их; предупреждение видно только с `--info`.

**Ограничение для Keenetic:** JSON-контроллер iplist отдаёт исходные CIDR без
upstream `replace`-замен широких сетей более узкими. Сети могут охватывать другие
сервисы; CLI предупреждает об этом при запросе CIDR с `--info`.

## Источник v2fly

Репозиторий: https://github.com/v2fly/domain-list-community

Отдельного сервисного API, аналогичного iplist, в документации не найдено.
Выбран готовый YAML-релиз, а не разбор исходных файлов `data/`:

```text
https://github.com/v2fly/domain-list-community/releases/latest/download/dlc.dat_plain.yml
```

Адаптер: `internal/v2fly/provider.go`.

- Формат: `lists` с полями `name`, `length`, `rules`.
- Включения и affiliations уже обработаны upstream-сборкой.
- Списки с префиксом `category` исключены.
- Любые имена списков с дефисом исключены. Это временный фильтр;
  дефис не всегда означает сборку нескольких сервисов.
- Возвращаются только правила `domain`.
- `full`, `keyword`, `regexp` игнорируются; предупреждения доступны с `--info`.
- Атрибуты вида `domain:example.com:@ads` не включаются в доменное имя.
- Имя списка — имя сервиса; основной домен по нему не угадывается.
- Поддерживается только `domains`. При `ips`, `cidrs` и `--site` источник не вызывается.
- YAML загружается один раз на команду и используется в памяти до завершения процесса.
  Между вызовами данные не сохраняются. Ответ ограничен 32 MiB.
- `--v2fly-url` позволяет заменить URL; пустое значение отключает источник на команду.
- YAML-парсер: `gopkg.in/yaml.v3 v3.0.1`, зависимости закреплены в `go.mod`/`go.sum`.

## Команды

```sh
bin/netcraze sources list
bin/netcraze services search telegram
bin/netcraze get telegram --type domains
bin/netcraze get discord --type domains --info
bin/netcraze get discord.com --type domains
bin/netcraze get telegram.org --site --type domains
bin/netcraze get telegram --type ips --family all
bin/netcraze get telegram --type cidrs --family ipv4
bin/netcraze get discord --type domains --v2fly-url ''
```

Флаги указываются после команды и позиционного аргумента.
Таймаут по умолчанию — 30 секунд на HTTP-запрос.

Коды завершения:

- `0` — успешный, частичный или пустой результат при хотя бы одном успешном запросе данных.
- `1` — недоступен весь каталог, все запросы данных неудачны либо ошибка записи вывода.
- `2` — неверные аргументы, неизвестный или неоднозначный сервис.

## Проверки

В ходе сессии успешно выполнены:

```sh
go test -race ./...
go test -race -cover ./...
go vet ./...
go build -o bin/netcraze ./cmd/netcraze
```

Тесты используют локальные HTTP-серверы и покрывают частичные сбои, отсутствие
постоянного кеша, нормализацию записей, выбор сервисов, фильтры v2fly,
игнорирование не-domain правил, объединение источников и вывод предупреждений.
Цвет дополнительно проверен через псевдотерминал, включая `NO_COLOR`.

Проверены реальные API/релиз. При сравнении Discord на момент проверки:

- iplist: 5784 уникальных домена;
- iplist + v2fly: 5788;
- добавлены `airhorn.solutions`, `airhornbot.com`, `bigbeans.solutions`,
  `watchanimeattheoffice.com`.

Количество записей и доступность источников могут меняться.

Go первоначально отсутствовал в PATH. Для проверок официальный toolchain был
скачан во временный каталог OpenCode без системной установки. Для самостоятельной
работы нужен Go 1.22+; инструкции находятся в `README.md`. Бинарник `bin/netcraze`
собран локально и исключён из Git.
